01

Authentication & session bootstrap

Users arrive from the HR Gateway portal with an AES-encrypted employee id in the URL. The default route is Home/Crypto, which decrypts the id, loads HR master data via stored procedure, and writes a server-side session before the dashboard renders with the user's permitted forms and menu.

02

Per-request authorization

Every feature action passes two action filters before it runs. [ValidateSession] enforces the 30-minute sliding timeout; [ValidateAccess] checks the caller's form permission against the cached grant list. Only then does the controller reach its service, the EF DbContext, and SQL Server — writing an audit row for any mutating action.

03

Training registration lifecycle

The core state machine. A schedule is published to AVAILABLE and registration is OPEN while seats remain and the start date is still ahead. RegisterTraining branches on employee level — level ≤ 5 needs superior approval first, higher levels skip to coordinator confirmation. Confirmation registers the trainee (and closes the class when full), monitoring records attendance and scores toward completion, and feedback closes the loop. Every transition fires an email and an audit log; cancelling a seat reopens registration.
